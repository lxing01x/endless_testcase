# endless_testcase 设计方案 v0.1

> 一句话定位：**一个用无限画布来"想"用例、用结构化表格来"管"用例的测试用例编写平台。**
> 画布负责发散与推演，表格负责规范与交付，二者共用同一份数据。AI（MVP 接 DeepSeek）作为画布上的"协作画师"，产出必须先预览、可撤销。

---

## 1. 目标用户与痛点

| 用户 | 场景 | 现有工具的痛 |
|---|---|---|
| 测试工程师 | 拿到需求文档，从零设计用例 | Excel 只能"填"，不能"想"；思路是网状的，表格是线性的 |
| 测试负责人 | 评审用例覆盖度 | 只能逐条读文本，看不出"场景之间的关系"和"漏了哪条分支" |
| 研发/产品 | 参与用例评审 | 不想读 200 行表格，愿意看一张图 |

核心洞察：**用例设计本质是"思维导图 + 决策树"的过程，而用例交付物是"表格"。**
主流工具（Excel、XMind、TestLink、禅道）都只覆盖其中一端。endless_testcase 的价值就是让两端**同源、实时互转、零迁移成本**。

---

## 2. 设计原则（这几条决定后面所有技术取舍）

1. **双视图同源（Single Source of Truth）**
   画布不是"另一个文档"，而是用例数据的另一种渲染。任何一个节点都对应一个用例（或一个用例分组的语义）。
   在画布上拖一个节点 = 改一条用例的"所属场景"；在表格里改标题 = 画布节点标题同步变。**永不做两套数据、事后合并。**

2. **结构可渐进，不强迫先建模型**
   允许用户先在画布上随手丢 20 个便签，再"一键收编"成正式用例。工具要先容纳混乱，再提供收敛路径。

3. **AI 是操作，不是自动改写**
   AI 的产出永远以"候选补丁（patch）"形式出现：预览 → 逐条采纳/丢弃 → 可 Ctrl+Z。绝不静默修改用户的用例。

4. **画布要能承载 1000+ 节点**
   用例稍微认真写就是几百个节点。"无限画布"必须真的无限，不能到 200 个节点就卡。分层细节（LOD）、视口裁剪、离屏渲染是硬需求。

5. **本地优先，可单机跑**
   MVP 一条 `docker compose up` 或 `npm run dev` 就能用，SQLite 落库；团队版再换 Postgres，不重构。

## 3. 信息架构

```
工作台
└─ 项目 Project（一个产品/一个迭代）
   ├─ 用例集 Suite（按需求/模块划分，可嵌套一层）
   │  ├─ 用例 Case（可挂在 Suite 下，也可只存在于画布）
   │  └─ 画布 Canvas（一个 Suite 对应一张主画布，可另建自由画布）
   ├─ 术语表 Glossary（AI 上下文用：业务名词、系统边界）
   ├─ 标签 / 自定义字段
   └─ AI 配置（项目级，可继承全局）
```

页面清单（MVP）：

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 项目列表 | 卡片式，显示用例数、最近编辑 |
| `/p/:pid` | 项目概览 | 覆盖度统计、最近画布、AI 用量 |
| `/p/:pid/s/:sid/table` | 表格视图 | 主战场：批量编辑、筛选、导入导出 |
| `/p/:pid/s/:sid/canvas` | 画布视图 | 同源数据的图视图，**URL 可分享到具体节点** |
| `/p/:pid/s/:sid/doc` | 文档视图（P1） | 只读排版，导出评审用 |
| `/settings/ai` | AI 配置 | DeepSeek Key / 模型 / 参数 / 连通性测试 |

关键交互：**表格 ↔ 画布 一个按钮切换，带过渡动画**，让用户建立"这是同一堆东西"的心智。

## 4. 核心：双视图同源模型

### 4.1 数据分层

```
Canvas (布局层，纯 UI)
 ├─ node: { id, caseId | groupId | note, x, y, w, h, collapsed, color }
 └─ edge: { id, source, target, kind }
Case (语义层，业务真相)
 ├─ id, suiteId, title, preconditions, steps[], expected, priority, type, tags[], status
 └─ groupId?（所属场景节点）
```

- **布局坐标只存在 Canvas 层**，不进用例表。删掉画布不会删用例。
- **节点 → 用例是 1:1（用例节点）或 1:N（场景节点作为分组）**。
- 关键规则：一个用例在画布上最多出现一次（主位置）。需要多处引用时用"引用节点"（只读镜像，P1）。

### 4.2 同步机制（工程上最容易翻车的地方）

采用 **命令模式 + 单向数据流**：

```
用户操作 → Command（AddNode / MoveNode / LinkCases / EditCaseField）
        → 乐观更新内存 store
        → 落库（防抖 400ms 批量写）
        → 广播给其他视图（同一 store，天然同步）
```

- 撤销栈基于 Command 的 inverse，画布和表格共用一个历史栈（在画布上画的、在表格里改的，一起 Ctrl+Z）。
- 冲突：MVP 单用户 + 单标签页锁（可选），Last-Write-Wins；多人协同留到 P2（Yjs/CRDT，节点坐标天然适合 CRDT）。

## 5. 画布设计（重点）

### 5.1 三种布局范式（用户自选，可混用）

| 范式 | 长什么样 | 适合 |
|---|---|---|
| **场景流（Flow）** | 从左到右：需求 → 场景 → 用例 → 步骤，连线表依赖 | 主线业务流程、状态机 |
| **发散树（Radial）** | 中心一个需求节点，向外炸开异常/边界分支 | 单功能点的用例发散（最常用的"想"模式） |
| **泳道矩阵（Swimlane）** | 横轴角色/端，纵轴场景，节点落格 | 多端、多角色系统（如 Web + App + 后台） |

实现上用一个 `layoutMode` 只是影响"自动布局算法"和"节点默认放置策略"，不锁死用户拖拽。

### 5.2 节点类型

| 类型 | 视觉 | 语义 | 对应数据 |
|---|---|---|---|
| 需求节点 Requirement | 圆角大卡，带来源链接 | 一段需求 / 一个用户故事 | `Requirement`（轻量表） |
| 场景节点 Scenario | 分组容器（可折叠） | 一个测试场景，内含多条用例 | 作为 `groupId` |
| 用例节点 Case | 中等卡片，显示标题+优先级色条+步骤数 | 一条可执行用例 | `Case` |
| 步骤节点 Step | 小卡，挂在用例节点下（可展开/折叠） | 显式画出步骤流时使用 | `Case.steps[i]` |
| 断言节点 Assertion | 菱形/绿色 | 预期结果，可挂多条 | `Case.expected` 片段 |
| 数据节点 Dataset | 表格缩略卡 | 测试数据、参数组合 | `Dataset` |
| 便签 Note | 黄色便利贴 | 待办、疑问、灵感（未结构化） | `Note`（独立表） |
| AI 建议节点 | 虚线边框 + 闪光 | AI 生成的候选，未采纳 | 临时态，采纳后转正式 |

**卡片折叠态（LOD）很重要**：缩放 < 40% 时只画色块 + 标题首行；40%~80% 画标题 + 优先级；> 80% 画完整步骤。这是撑住 1000 节点的关键。

### 5.3 连线语义（不是随便连线）

| 连线 | 语义 | 用处 |
|---|---|---|
| 实线箭头 | 依赖：A 通过后才能测 B | 生成执行顺序建议 |
| 虚线箭头 | 数据流：A 的输出作为 B 的输入 | 参数化联想 |
| 红色虚线 | 冲突/互斥 | 提示覆盖矛盾 |
| 无箭头连线 | 关联（同组） | 弱关系，仅视觉 |

连线创建时弹一个 4 选 1 的小气泡（默认实线），避免用户思考成本。

### 5.4 交互清单（MVP 必须有的）

**基础**
- 拖拽移动、框选多选、Shift 加选、空格/中键平移、滚轮缩放（Cmd+滚轮精细缩放）
- 小地图、缩放百分比、缩放到选区（`Shift+1`）、回到全览（`Shift+0`）
- 对齐吸附（8px 网格）、智能对齐参考线、等距分布
- 右键菜单：新建用例/场景/便签、转为用例、复制、分组、锁定、删除
- 双击空白 = 快速新建用例（就地输入标题，Enter 确认，连续创建）

**提效**
- 选中多个便签/节点 → **"收编为用例集"**（一键生成结构化用例，AI 补全步骤）
- 画布内搜索（`Cmd+F`）→ 命中节点高亮并居中
- 聚焦模式：双击场景节点 = 只显示该分组（面包屑返回）
- 模板：内置"登录鉴权""支付下单""权限矩阵""文件上传"等场景模板，一键落图
- 从用例表格拖一行到画布 = 生成节点并定位

**快捷键（常用）**

| 键 | 行为 |
|---|---|
| `N` | 新建用例节点 |
| `S` | 新建场景（分组） |
| `Tab` | 选中节点后新建子节点并连线 |
| `Enter` | 编辑选中节点标题 |
| `Cmd+D` | 复制 |
| `Cmd+Z / Shift+Cmd+Z` | 撤销/重做（跨视图） |
| `Cmd+K` | 打开 AI 指令面板 |
| `L` | 自动布局（dagre） |
| `Cmd+/` | 快捷键帮助浮层 |

### 5.5 自动布局

- 引擎：`dagre`（分层，快）为主，`elkjs`（复杂正交路由）作为可选。
- 触发：手动 `L`、新节点批量生成后、切换 layout 范式时。
- 必须支持"锁定局部"：用户手动摆好的区域不被自动布局打乱（用 `pinned: true`）。

### 5.6 画布 → 用例的映射规则（写清楚，否则实现会拧）

| 画布元素 | 映射 |
|---|---|
| 场景节点（分组） | `Case.groupId`，同时生成 `suite.section` |
| 用例节点标题 | `Case.title` |
| 用例节点下挂的步骤子节点 | `Case.steps[]`（顺序 = 纵向 y 坐标排序） |
| 断言节点（挂在用例后） | `Case.expected` |
| 数据节点（连线到用例） | `Case.datasets[]` |
| 便签（未收编） | 不参与导出（可在导出时勾选"包含便签"） |

## 6. 常规功能（表格视图）

### 6.1 用例字段模型

```ts
type Case = {
  id: string
  suiteId: string
  groupId?: string          // 场景
  title: string
  preconditions: string
  steps: { action: string; data?: string }[]
  expected: string
  priority: 'P0'|'P1'|'P2'|'P3'
  type: '功能'|'接口'|'性能'|'兼容'|'安全'|'异常'
  tags: string[]
  status: 'draft'|'reviewing'|'approved'|'deprecated'
  assignee?: string
  custom: Record<string, any>   // 自定义字段（项目级 schema 定义）
  aiMeta?: { generated: boolean; model?: string; promptVersion?: string }
  createdAt, updatedAt, order: number
}
```

### 6.2 表格能力

- 行内编辑、多行粘贴（从 Excel 直接 Ctrl+V 进来）、拖拽排序
- 列筛选 / 分组 / 排序 / 列显隐 / 列宽持久化
- 批量操作：改优先级、打标签、改状态、删除、生成画布节点
- 虚拟滚动（1w 行不卡）
- 导入：Excel(.xlsx)、CSV、Markdown 表格、XMind（P1）、测试用例模板
- 导出：Excel（带合并单元格的"场景-用例"两级表头）、Markdown、JSON、可分享 HTML
- 版本：每次保存生成快照（小型 delta），可 diff 两版（P1）
- 评审：评论（锚定到用例字段）、@提及、状态流转（P1）

### 6.3 覆盖度看板（低成本高价值）

用画布结构直接算：需求节点数 vs 已覆盖需求数、每个场景的用例数、P0 用例占比、未连线的孤儿用例。这是"画布"相比表格的独家收益，务必做。

## 7. AI 能力设计（MVP：DeepSeek）

### 7.1 配置项

DeepSeek 兼容 OpenAI 协议，直接用 `baseURL = https://api.deepseek.com`。

| 配置 | 默认 | 说明 |
|---|---|---|
| Base URL | `https://api.deepseek.com` | 支持自定义代理 |
| API Key | — | **后端加密存储（AES-256-GCM），永不回传前端明文** |
| Model | `deepseek-chat` | 可切 `deepseek-reasoner`（复杂发散用，慢且贵） |
| temperature | 0.3（生成）/ 0.7（发散） | 按能力预设 |
| max_tokens | 4096 | |
| 超时 / 重试 | 60s / 2 次指数退避 | |
| 项目术语表注入 | 开 | 提升领域准确率 |

连通性测试按钮：发一条 `max_tokens: 5` 的请求，返回延迟与模型名。

### 7.2 能力清单（P0 三条，必须做扎实）

| 能力 | 入口 | 输入 | 输出 |
|---|---|---|---|
| **A1 需求→用例** | 需求节点右键 / 画布空白处 | 需求文本 + 术语表 + 已有用例标题列表（去重） | 候选用例节点树（场景→用例→步骤） |
| **A2 场景发散** | 用例节点右键"帮我想想还漏了什么" | 该用例 + 所属场景 + 兄弟用例标题 | 边界值/异常/权限/并发 候选（6~10 条，去重后） |
| **A3 步骤规范化** | 选中用例 → AI 面板 | 用例标题 + 粗糙描述 | 规范化的 前置条件/步骤/预期 |

P1：用例查重与合并建议、评审意见生成、自然语言改图（"把支付相关的用例都放到右边并连起来"）、测试数据生成。

### 7.3 上下文组装（省钱又准的关键）

```
system: 角色 + 输出 JSON Schema（强约束）+ 领域术语表（≤500 tok）
user:   任务描述 + 选中节点摘要 + 1 跳邻居标题（≤30 个，只给标题）
        + 已有用例标题列表（用于去重，只给 title，截断到 200 条）
        + 用户补充要求
```

- 预算控制：单次请求 ≤ 6k input tokens；超出则先做本地摘要（标题截断 + 分页）。
- 缓存：`hash(输入 + 参数)` → 结果缓存 24h，避免重复烧钱。
- 用量记录：每次调用写 `ai_usage` 表（tokens、耗时、能力类型、是否采纳），项目概览页出成本图。

### 7.4 输出契约（决定了 AI 能不能"落到画布上"）

强制 JSON，前端解析失败则重试一次（附带错误信息），仍失败降级为"纯文本建议卡"。

```json
{
  "nodes": [
    {
      "tmpId": "n1",
      "type": "scenario",
      "title": "支付-优惠券叠加",
      "parentTmpId": null
    },
    {
      "tmpId": "n2",
      "type": "case",
      "parentTmpId": "n1",
      "title": "满减券与折扣券同时使用时仅生效优惠力度最大的一张",
      "priority": "P0",
      "steps": [{"action": "..."}],
      "expected": "...",
      "tags": ["优惠券"]
    }
  ],
  "edges": [{"source": "n1", "target": "n2", "kind": "contains"}],
  "notes": "本次仅覆盖正向与金额边界，未覆盖并发场景"
}
```

### 7.5 交互流程（AI 绝不静默写入）

```
选中节点 → Cmd+K / 右键 AI
  → 侧边抽屉：选能力、填补充说明、[生成]（SSE 流式，300ms 内出首字）
  → 生成结果以"虚线幽灵节点"出现在画布右侧空白区（不落库）
  → 顶部浮条：采纳全部 / 逐条采纳 / 重新生成 / 丢弃
  → 采纳后变实心节点，可 Ctrl+Z 整体回滚（一次 AI 操作 = 一个 Command）
```

**视觉要点**：AI 生成过程中节点是"流动的虚线 + 微光"，落地动画 200ms，让用户明确感知"这是 AI 提的，我批准了它"。

### 7.6 安全与成本

- Key 只在后端；前端只看到 `configured: true` 和"上次测试时间"。
- 限流：每项目 20 次/分钟；单日 token 上限可配。
- 日志脱敏：不记录完整 prompt 中的敏感字段（可开关）。
- MVP 不做多租户计费，只做用量统计。

## 8. 技术架构

### 8.1 选型

| 层 | 选型 | 理由 / 备选 |
|---|---|---|
| 前端框架 | React 18 + TypeScript + Vite | 生态最全，画布库都优先支持 React |
| 画布引擎 | **@xyflow/react (React Flow 12)** | 节点化编排、自定义节点、内置 minimap/连线/框选，改造成本最低。<br>备选 `tldraw`：白板手感更好、手绘/自由绘制强，但"结构化节点 + 数据绑定"要自己搭很多；若产品更偏"白板优先"再换。<br>自研 Canvas/Konva：只有在节点数 >5k 且有极致性能诉求时才考虑。 |
| 状态 | Zustand + Immer | 轻、易做命令栈；配合 `zustand/middleware` 做持久化 |
| UI | Tailwind + shadcn/ui + Radix | 快速出专业观感 |
| 表格 | TanStack Table + 自研虚拟化（或 AG Grid Community） | 多行粘贴/行内编辑自己控更灵活 |
| 后端 | Node 20 + Fastify（或 NestJS） | MVP 用 Fastify 够轻 |
| ORM/DB | Prisma + SQLite → Postgres | 换库仅改 datasource |
| AI SDK | 直接 `fetch` OpenAI 兼容接口（或 `openai` npm） | 不引重框架，方便加 DeepSeek 特有参数 |
| 实时/流式 | SSE | 比 WebSocket 简单，够用 |
| 部署 | Docker Compose（web + api + volume） | 单机一键起；后续可拆 |

## 9. 数据模型（草案）

```prisma
model Project {
  id String @id @default(cuid())
  name String
  description String?
  aiConfig Json?          // { baseUrl, model, temperature, keyCipher }
  createdAt DateTime @default(now())
  suites Suite[]
}

model Suite {
  id String @id @default(cuid())
  projectId String
  name String
  order Int @default(0)
  project Project @relation(fields: [projectId], references: [id])
  cases Case[]
  canvases Canvas[]
}

model Case {
  id String @id @default(cuid())
  suiteId String
  groupId String?         // 场景（画布场景节点 id）
  title String
  preconditions String @default("")
  steps Json              // [{action, data}]
  expected String @default("")
  priority String @default("P2")
  type String @default("功能")
  tags Json               // string[]
  status String @default("draft")
  order Int @default(0)
  aiMeta Json?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  suite Suite @relation(fields: [suiteId], references: [id])
  @@index([suiteId, groupId])
}

model Canvas {
  id String @id @default(cuid())
  suiteId String
  name String @default("主画布")
  layoutMode String @default("flow")
  viewport Json?          // {x,y,zoom}
  nodesJson Json          // 布局层：节点坐标/尺寸/折叠
  edgesJson Json          // 连线
  suite Suite @relation(fields: [suiteId], references: [id])
}

model Note {
  id String @id @default(cuid())
  canvasId String
  content String
  x Float
  y Float
  color String?
}

model AiUsage {
  id String @id @default(cuid())
  projectId String
  capability String       // requirement2case | diverge | normalize
  model String
  inputTokens Int
  outputTokens Int
  latencyMs Int
  adopted Boolean @default(false)
  createdAt DateTime @default(now())
}
```

> 为什么画布布局用 `nodesJson` 而不是给每个节点建表：布局是高频、整体读写、无需单独查询的 UI 状态，JSON 列 + 前端 diff 增量保存性能最好；用例语义仍在 `Case` 表，保证可查询可导出。若未来要多人协同，再拆 `CanvasNode` 表交给 Yjs。

## 12. 非功能指标

- 画布 1000 节点：拖拽 ≥ 50fps，首屏 < 1.5s（LOD + 视口裁剪）
- 表格 10,000 行：滚动不白屏（虚拟滚动）
- 用例保存：本地乐观更新 < 16ms 感知，落库防抖 400ms
- AI 首字延迟 < 2s（SSE），单次生成 P95 < 25s
- 断网：画布编辑可继续（IndexedDB 暂存），恢复后补传

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 画布与表格同步出现"幽灵数据" | 信任崩塌 | 单一 store + Command 模式，禁止任何一方直写另一方的本地状态；写集成测试覆盖双向同步 |
| 节点多了卡顿 | 核心体验失效 | 从第一天就做 LOD + `onlyRenderVisibleElements`；1000 节点作为验收基准 |
| AI 输出 JSON 不稳定 | 落图失败 | response_format=json_object + zod 校验 + 一次重试 + 文本降级 |
| 用户不接受"画布=数据" | 学习成本 | 提供"自由画布"模式：便签不强制结构化，收编才转用例 |
| React Flow 自由度不足（想做手绘/自由连线） | 观感受限 | 自定义节点 + 自定义边已能覆盖 90%；真需要白板手感再嵌 tldraw 做"草图区" |
| DeepSeek 限流/不可用 | 功能不可用 | 队列 + 重试 + 明确错误提示；AI 是增强不是依赖，关闭不影响主流程 |

## 14. 待你确认的 5 个问题

1. **形态**：本地单机（自己/小团队用）还是云端多租户 SaaS？影响鉴权与存储选型。
2. **画布主导权**：画布是"主入口"（打开项目先进画布），还是"辅助视图"（主入口是表格）？我倾向 **画布优先**，这才是差异化。
3. **"libtv 那种"具体指什么手感**：自由白板（随手画、无网格、便签任意贴），还是节点编排（卡片+连线+自动布局）？我按**节点编排为主 + 便签自由区**设计，若你更想要纯白板我会把 React Flow 换成 tldraw。
4. **要不要执行能力**（跑用例、记录结果、对接自动化）？MVP 我建议**只写不跑**，先把"写"做到极致。
5. **AI 成本归属**：用户自填 Key，还是平台统一 Key（需计费）？MVP 建议自填 Key + 用量统计。
